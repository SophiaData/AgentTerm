# 功能台账（老板的仪表盘）

> 状态流转：待办 → 进行中 → 待验收（老板亲手试）→ 完成；搁置 = 暂不做。
> 规则：全表同时只允许一个「进行中」；「待验收」攒到 3 个先请老板验收再开新活。
> 验收标准必须可机械核对；「老板怎么验证」必须是非程序员能照做的一步操作。
> **验收标准冻结**：某行验收标准经老板确认后，日常迭代只许改「状态」列；要动验收标准本身，必须在汇报中向老板点名说明。

**#12 当前实现（2026-11-21）**：完成受管尝试启动后的进程身份持久化、后端停止请求、只读恢复评估与显式安全接续基础链路。启动事件先落盘，子进程加入隔离范围后记录 `pid`、可执行文件和平台可用的启动 token；身份写回失败会停止子进程，不继续执行。停止请求具备幂等性，先写入运行中的启动事件，再请求停止；确认后写入 `Unknown` 终止事件，确认失败仍保留 `RecoveryRequired` 占用。重启核实时，无身份的启动事件标为启动边界未知，匹配身份且仍存活/已退出/PID复用/查询不确定分别分类；评估只读，不释放、不重派。显式接续会在人工确认入口中再次核实，只有所有未结束旧尝试均为 `Exited` 时才将账本迁移到新 owner 的 `RecoveredReserved`，并使用新 revision/dispatch 创建尝试；旧回报不能结束新尝试。正常退出写入已确认停止证据；超时、异常、结果未知或停止不确定保留待核实状态。文档日志允许同一启动事件只做一次受限身份补写，并保持重复回写幂等；受限 `dispatch_controlled_task` 已接入前端，但只接受已关联的同项目 Claude 会话，不开放真实CLI接管、暂停按钮、外部作业撤销或用户验收入口。

**#12 功能侧接入（2026-11-21）**：任务抽屉现在会展示待核实执行尝试的进程观察结果（启动边界未确认、仍在运行、PID已复用、无法确认、已确认退出），并提供重新核对入口。只有最新 task ID/generation/revision 仍匹配，且后端二次核对所有旧尝试均为 `Exited` 时，才允许点击“核实并接回任务”；接回只迁移到新 owner 的 `RecoveredReserved`，不启动 CLI、不自动完成任务。新增 `resume_main_task_after_recovery` Tauri command，前端任务卡和 Rust command 测试已覆盖活进程阻断、无身份阻断、全部退出接回、重复点击和版本过期边界。

**#12 会话关联（2026-11-21）**：任务抽屉现在可以把当前运行中的同项目 CLI 会话显式关联到任务记录。后端通过 `associate_task_session` 核对 session ID 仍对应运行中的 PTY、项目路径一致、task/generation/revision 未过期；任务文档持久保存工具、项目和会话 ID，同一会话重复关联幂等，换绑拒绝。前端测试和 Rust 文档测试已覆盖同项目显示按钮、跨项目隐藏、持久化和写一次约束。关联已进入受控派发前置链路，#12 仍未完成。

**#12 受控派发最小入口（2026-11-21）**：新增 `dispatch_controlled_task`。任务抽屉只有在任务仍处于 `reserved/recoveredReserved`、计划完整、任务记录已绑定当前运行中的同项目 Claude 会话时显示“开始受控执行”。Rust command 再次校验 session 元数据、任务 ID、代次、账本 revision、计划归属和工具类型；relay 固定为 Claude 无工具、无 MCP、无外部操作，执行 Agent 与验收 Agent 串行运行。重复点击、过期票据、跨项目、无绑定、会话结束和 Codex/Agy 会话均拒绝。结果回写任务尝试记录，暂不自动完成、释放占用或接管当前终端。下一项是状态联动与停止/完成释放的受控入口。
