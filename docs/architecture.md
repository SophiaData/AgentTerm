## 硬约束（动架构、加依赖前逐条核对）

- 依赖白名单制：新依赖必须登记用途与理由；无理由不引入。
- 渲染进程禁止直接访问 Node.js、文件系统或任意进程；所有桌面能力通过受校验的 Tauri 命令暴露。
- AI 工具只能从已登记工具及其可执行文件路径启动；首版不接受前端传入任意 shell 命令。
- 项目路径必须是存在的目录；移除项目只改 AgentTerm 数据，不删除或修改项目文件。
- 一个会话只绑定一个 PTY；切换标签页不得重复启动进程，关闭运行中会话必须经确认。
- 终端输出通过事件发送；禁止无界缓存、无界循环和无界自动重试，退出后必须释放读取线程与句柄。
- 不在日志、事件、测试快照或提交中记录密钥、口令、令牌及完整敏感环境。
- 本地设置写入应用数据目录；项目记录采用下述受锁保护的追加快照，不依赖重命名。损坏时保留原文件并显示可理解的错误。
- 质量门必须包含格式、lint、类型检查、前端测试、Rust 测试和模板契约测试；不得以静态检查冒充运行测试。
- 发布保持手动；CI 可构建安装包，但不能因普通推送自动创建正式 Release。
- 首版只支持 macOS Apple Silicon（`aarch64-apple-darwin`）和 Windows x64；本地开发不要求完整 Xcode。

## 项目文件浏览（2026-11-23）

- 复用已登记项目，后端 `project_files` 提供列目录、预览文本、打开所在目录三个命令；前端不能指定任意绝对路径或 shell 命令，不增加通用文件系统插件权限。
- 相对路径逐段校验，拒绝上跳、绝对路径、替代数据流、符号链接和 Windows reparse point；规范路径必须位于项目根内。目录最多返回 1000 项，文本最多读取 1 MiB，拒绝非普通文件和非 UTF-8/二进制内容；读取在阻塞任务池完成，不修改用户文件。
- 前端为每个项目建立独立状态；目录与文件请求具有序号，过时响应不覆盖新选择，关闭预览使未完成请求失效。文本用 React 纯文本节点呈现，不执行文件中的 HTML 或脚本。目录仅在展开或刷新时读取，文件仅在点击或刷新已选文件时读取。
- 系统资源管理器入口只接收经校验的项目目录或文件的父目录，调用固定的 Windows Explorer/macOS open；不运行被选中的文件。与终端及任务记录共用现有工作区，窄窗显示可关闭的抽屉。

## 数据工作台运行契约（2026-11-20，部分实现与后续约束）

### #12 恢复验收修复（2026-11-21，当前实现增量）

以下是对历史切片的增量约束：受限派发与停止命令已经接入，早期切片中“尚无入口”的描述仅代表当时的边界。完整原生验收、外部作业撤销、证据放行与完成释放仍独立验收。

- 崩溃后账本可能仍为 `running/verifying/pausing/waitingInput`，快照按旧 owner 加执行记录返回只读恢复评估，不为展示而改写账本。接回时核对当前版本、所有已记录尝试的 `Exited`、后台派发已结束；跨 owner 时还在账本锁内确认旧协调进程已经退出。存活/未知 owner、缺进程身份、存活或复用 PID 继续阻断。接回增加 revision，保持任务、代次、文档与占用；旧进程不能以旧票据回写。
- 停止按钮先持久化原始原因再设置停止令牌；relay 识别既有合法请求，不以另一原因覆盖它，停止确认仍由进程层生成。
- 11 月 23 日补修：Unix 退出证据只来自合法 PID 的 `kill(pid, 0)` 明确 ESRCH，Linux 的 `/proc` 仅核身份；macOS 尚无启动身份探针，存活 PID 返回 `Unknown` 并阻断。relay 已写运行意图后的异常收尾有界推进待核实，绑定任务/代次/owner 和本次版本，不能覆盖后来的派发或审批状态。写入仍失败时，同 owner 的空闲后台加 `running/verifying/pausing` 显示只读恢复入口；人工接回在运行锁内重核进程退出后先写待核实、再接回，失败保留占用。
- `reassociate_task_session_after_recovery` 仅在当前 owner 的 `recoveredReserved` 阶段执行，账本锁覆盖文档变更。新会话必须仍在运行、属于相同项目和工具；原会话仍存活时拒绝。文档添加有界的 `sessionLinkHistory`（32 条），换绑时追加旧关联，重复同值幂等；不允许静默覆盖、回退历史或复用旧关联 ID。空历史字段不序列化，保持旧文档摘要校验；旧版本遇到新字段会失败关闭，回滚不得直接覆盖新文档。
- `workbench_snapshot.dispatchActive` 来自当前后端运行状态，界面只在其为真时每 350ms 核对，最长 650 秒，结束或卸载时停止；读取失败保持明确错误，不能把提交回执当成接力完成。恢复后重新派发创建新尝试，不等于 CLI 对话原生 resume。

本节约束工作台实现。已实现 `task_ledger.rs` 单任务预留账本、`task_commands.rs` 的账本与任务文档命令、`task_relay.rs`/`task_process.rs` 原生顺序接力核心，以及 `task_document.rs`/`TaskWorkbench.tsx`/`workbenchState.ts` 的任务页与产物引用。真实 CLI 派发、工具权限、持久队列、完整恢复与完成释放仍未形成闭环。产品范围以 [PRD](PRD.md) 为准，开发纪律见 [workflow](workflow.md)，实施顺序与当前状态以 [tasks](tasks.md) 为准。

### 功能 9 当前实现与取舍

- 账本使用 Rust 标准库 OS 文件锁和带版本的追加记录，没有新增第三方依赖。初始化与所有读写先取得固定 `.lock` 伴随文件的锁，再创建或打开数据文件，避免首次建文件的空内容窗口被其他操作读取；单次读、校验与追加保持锁直到 `sync_all`。进程退出释放 OS 锁，但不释放持久任务占用。
- 首轮只记录当前占用、任务/项目/进程归属、代次、版本和阶段，无关系查询需求，因此暂不采用原规划首选的 SQLite。任务队列与完整事件索引增长到后续阶段时，再按迁移与并发测试评估事务数据库；不把当前文件实现称为通用数据库。
- 文件头版本、完整记录、校验和、连续版本及合法状态转换逐项验证；未知版本、截断尾部和损坏记录失败关闭，不截断或修复原件。文件上限 8 MiB，超限停止并提示归档，当前不提供自动归档。校验和仅检测意外损坏，不证明作者身份；同一 OS 用户恶意改写、删除或回滚整个文件不在该机制的保护范围内。
- 每个 OS 用户固定使用 Tauri `local_data_dir()` 下的 `agentterm-main-task-ledger.log` 与同名追加 `.lock` 的伴随文件；所有项目与窗口共用该位置。文件名不随 schema 版本变化，避免新旧程序通过另开账本绕过占用。目录必须已经存在，只在显式初始化命令中创建文件，不在启动或查询时建目录或文件。锁文件不移除或替换。
- 前端不能指定账本路径或进程归属；归属由后端生命周期生成，预留时核对已登记项目。重启后的旧归属显示 `recoveryRequired`，不允许自动取消或重领。
- 四个命令为 `task_ledger_initialize`、`task_ledger_snapshot`、`claim_main_task`、`cancel_main_task_reservation`。取消仅允许同一后端归属、相同代次与版本、尚未记录执行意图的 `reserved` 状态。
- `set_phase` 仅供后续可信原生调度器调用，不暴露给前端。进入运行、验收、等待、暂停或待核实后不能回到 `reserved`，也不能用取消预留释放。安全停止与完成释放属于后续恢复功能；本轮不提供自述“已停止”的通用释放接口。
- 账本命令不调用 CLI 或线上系统，原有手动终端不经过账本；#10 的原生接力核心单独验证。完整工作台约束只能在后续受管入口接入后验收；当前证据证明受管账本操作的单占用，不证明所有终端已经单并发。

### 功能 10 当前后端切片

- 原生 `task_relay::run` 接收已预留账本的任务票据，核对项目真实路径、后端归属、代次、版本与 reserved 状态。以账本版本比较和同步写入记录 running 后才启动；同一票据只能启动一次。工作进程返回并确认停止后，先持久记录 verifying 再开启新的审查进程。
- 适配 Claude（stdin + JSON）与 Cursor（独立 argv 参数 + JSON）。只解析终态 result/success/is_error=false 和非空 session_id；内部报告须具有固定版本、任务/代次/尝试/角色、允许的状态及有界摘要。普通文本、错误身份、未知字段、重复会话均待核实，退出 0 不代表报告有效。reviewer 的 pass/fail 只是意见，完整产物证据门禁属于 #13。
- 回报不合规、启动失败、超时、超限、退出异常或残留进程进入 recoveryRequired；worker 明确 blocked 或两阶段完成进入 waitingInput。所有路径保留主任务占用，没有自动重试、取消释放或生产完成操作。重启沿用 #9 的旧归属保护，不能自动重派；原 `run` 结果仅在返回值内；#11 新增 `run_recorded` 可持久记录尝试事件和摘要，恢复 UI 属于 #12。
- 进程输出上限 256 KiB，目标与报告摘要各 8 KiB，stdin 上限 32 KiB，单次执行上限 300 秒，停止与管道回收有界。stderr 丢弃、不写原始日志；stdout 仅内存解析。Unix 使用独立进程组，Windows 使用启动时挂起、先加入禁止逃逸的 Job Object 再恢复线程；退出残留即使清理成功也不接力。Unix 进程主动 setsid 逃逸不是此进程组机制可证明的隔离边界。
- Windows 仅接受 `.exe`，拒绝 `.cmd/.bat/.ps1` 的 shell 包装；当前本机 Cursor `.cmd` 不满足此限制，不能宣称已经实测可用。Cursor 适配器只查 `cursor-agent`，避免把通用 `agent` 名误识别；不修改既有三工具手动终端注册表。Claude 禁用内置工具及 MCP，Cursor 请求 ask 模式；这些参数不等于已验收的跨工具权限隔离。
- 因 CLI 的项目 hooks、全局配置、网络与写入能力尚未逐项验收，本切片仅提供原生后端接口和离线协议测试，**没有新增 Tauri 派发命令、UI 按钮或自动运行入口**。不称为受控只读执行能力，不接生产，不运行本机真实账号 CLI，不改全局配置。真实双 CLI、完整入口、进程逃逸、权限隔离与资源基线属于未验项目。
- JSON 解析直接依赖已在锁文件中的 `serde_json`，用于严格校验报告，避免手写解析器；没有新服务、数据库或运行时。CLI 协议依据官方 CLI reference 与 output-format 文档核对于 2026-11-19，兼容性须以实际安装版本验收。

### 功能 11 任务页与产物引用

- 桌面默认进入项目/CLI会话工作区，任务记录作为默认收起的辅助抽屉。任务卡展示目标、负责人、范围、产物目录及执行/验收两个步骤。主任务阶段来自原账本，尝试阶段来自事件；结果已提交不显示为业务完成。页面提供显式刷新，并在返回窗口时核对状态；读取失败保持提示并阻止操作，不把旧数据显示成最新。
- 新增 `workbench_snapshot`、`create_workbench_task`、`attach_task_plan`、`reference_task_artifact`、`preview_task_artifact`。所有变更绑定当前任务、代次、版本与后端归属；预留前校验已登记项目与已有目录。补计划只用于尚未派发的任务；旧进程归属默认只读，B1另有下述核实恢复入口。原取消入口仍只取消未派发预留，不提供通用释放。
- 计划与事件使用固定本机账本目录内按任务哈希/代次区分的追加文件。稳定伴随锁保护首次初始化和读改写；账本与文档在事务退出时显式解锁，避免并发 fork 暂时持有复制描述符导致锁延迟释放；每条记录带 SHA-256，校验 schema、连续文档版本、不可变计划、事件/产物单调增长，截断或损坏拒绝自动修复。上限 8 MiB，单记录 512 KiB、128 事件、32 产物版本；无新目录、后台服务或数据库。
- 占用账本与文档是两个事务。先验证计划、再预留、再保存；文档失败保留预留，不自动释放。页面可为当前未派发且缺文档的任务补计划，已存在文档不覆盖。快照读取前后比对账本版本，拒绝混合不同任务；这是失败关闭的两文件流程，不宣称跨文件原子事务。
- 原生 `task_relay::run_recorded` 在启动前保存尝试意图，退出后保存报告摘要或故障状态；写入失败阻断接力并保持占用。事件按代次/账本版本/角色生成稳定 ID 与序号，重复相同事件无操作、同 ID 不同内容拒绝、乱序排序保存。页面按尝试取最新事件并拒绝较旧快照，避免重复或回退。`dispatch_controlled_task` 只接受已有任务、有效 `sessionLink`、仍运行的同项目 Claude 会话和最新账本票据，再由 Rust 重新构造只读 relay 计划；不接管当前终端，不扩大工具权限。
- 产物只登记已有文件：输出目录必须为项目内已有真实目录；输入仅允许相对路径，拒绝 `..`、绝对路径、最终文件链接和解析后越界。允许 SQL/Markdown/TXT/JSON，要求 UTF-8 且不超过 1 MiB。保存内容摘要、字节数和版本，重复同内容不新增；预览重新读取并核对摘要，改版后旧版本不能冒充当前文件。只保存引用，不复制文件正文，不执行/覆盖 SQL。
- `sha2` 0.10.9 直接复用锁文件已有版本，用于文档完整性与产物版本标识。摘要不是作者认证；同一 OS 用户恶意改写、文件路径竞争或硬链接攻击不属于本机文件机制的隔离保证。任务目标、报告摘要和用户选择的产物可能包含业务内容，应由使用者遵守现有凭据规范；不自动扫描项目，也不保存原始 CLI 日志。
- 当前可验的是本地计划、记录、产物引用流程、未派发预留恢复和受限受控派发的静态/单元闭环。缺少历史任务列表、持续状态推送、工具端权限隔离、运行中恢复/完成释放与独立证据放行；主任务占用、摘要变化和报告意见不能代替这些后续门禁。
- 功能侧恢复核实已接入任务抽屉：`workbench_snapshot` 只读返回每个运行中尝试的进程观察结果，`resume_main_task_after_recovery` 在同一 command 内重新探针并校验 task ID、代次、revision、任务计划和全部 `Exited` 条件，然后才将账本迁移为 `RecoveredReserved`。该入口只恢复任务管理权，不启动 CLI、不自动完成、不释放占用；真实会话关联和受限 `dispatch_controlled_task` 已接入，真实桌面派发仍待验收。
- 真实手动 CLI 会话可通过 `associate_task_session` 显式绑定到当前任务文档。后端同时核对 session ID 仍对应运行中的 PTY、项目路径与任务项目一致、账本票据未过期；文档中的 `sessionLink` 只允许从无到有或重复同值写入，禁止静默覆盖其他会话。该绑定建立可追溯关系，但不等于受管派发、权限隔离或外部会话接管。

### 职责与持久状态

- 桌面沿用 Tauri/Rust，现有 TUI 保留启动入口；编排核心独立于界面，未来接入同一核心的入口共享同一个执行账本。
- 业务身份以 Teambition 的组织、项目和任务 ID 组合为准；本地 `task_id` 标识执行计划，`step_id` 标识步骤，`dispatch_id` 标识一次实际执行尝试。重试创建新尝试并引用旧尝试，不能覆盖旧证据。
- 现有项目与设置存储保持其职责。当前单任务占用使用上方受限追加账本；后续本地队列、步骤、尝试与证据索引按实际需求扩展，不复制第二份业务任务状态。
- 账本使用版本化 schema，未知版本或损坏记录失败关闭；迁移先备份并验证可恢复。数据文件使用已存在、经校验的目录，初始化不自动创建父目录。
- 产物引用至少包含路径、内容摘要、输入指纹、检查器版本和产生时间。原始日志按需引用并有容量上限；认证信息和敏感环境不进入账本、日志、测试快照或同步内容。

### 单主任务与执行顺序

- `max_active_main_tasks = 1` 是同一本地应用实例体系跨项目、跨窗口、跨受管入口的硬约束，不是每个项目各有一个名额。多进程打开同一账本时也须原子竞争唯一占用。
- 首版 `max_active_dispatches = 1`，执行与验收顺序接力。主任务等待执行者时，主 Agent 只协调该任务；派发子任务不能成为另开主任务的理由。
- 运行、验收、等待输入、等待授权、正在暂停、故障待核实均保留主任务占用。完成或取消前核实执行者及关联外部作业已结束；安全暂停须保存断点且确认已停止或可安全接续后才能释放占用。
- 占用、代次、步骤转换和事件写入必须原子化；同时启动只允许一个成功。前端禁用按钮只作体验提示，Rust 入口和账本仍必须检查。
- 手动终端能力维持历史用途；它不自动受账本控制。接入受管任务必须登记归属并经过同一检查，不能用手动入口绕过受管派发。工作台不宣称控制用户在应用外另起的 CLI。

### 执行适配与结果回报

- 已登记适配器提供能力发现、启动、输入、状态、结果回报、停止与恢复核实。差异由适配器显式声明，不假定所有 CLI 都能恢复原会话或都提供同样的 hooks。
- 每次派发包含任务/步骤/尝试 ID、目标、已确认事实、输入版本、读写范围、允许工具、验收标准和产物位置。默认验收模板标为候选，不冒充业务方确认。
- Agent 报告「完成」、CLI 退出0或收到 Stop 仅触发结果收集；必须检查结构化结果、产物和证据。CLI 缺少结构化能力时，使用经验证的包装协议；无法验证则返回待核实。
- 执行者交回确定版本并停止修改后，才启动独立审查上下文。业务与规范审查分别保存结果；作者不得充当自己的独立审查者。
- 同一事件按尝试 ID 与事件 ID 去重；只允许当前代次推进当前步骤。旧尝试的迟到结果可保留审计，但不能将新尝试或新任务标记完成。

### 中断、停止与恢复

- 启动前先记录派发意图；进程创建前后崩溃必须能区分待启动、已启动和未知。不能为了恢复方便直接重复创建进程。
- 重启后先核实执行者、工具调用及外部实例状态，之后才决定重新连接、接续或创建新尝试。PID 可能复用，需结合实际启动身份，不能单靠 PID 或心跳超时判断进程已结束。
- Stop 请求、超时、窗口关闭和失联都不等于执行者或外部作业已停止。未知状态保持占用并提示人工核实；取消主任务不冒充撤销已提交的外部作业。
- 结果未知的外部操作先按实例或请求引用查明；只有能够证明未执行且允许安全重试，才提交新的尝试。自动重试须有有限预算和明确类别，禁止无限重试。
- 新旧实现同时运行、重复派发、迟到回报、退出残留与跨窗口竞争都是必测失败场景，不能只测试顺利完成。

### 权限、hooks 与业务验收

- hooks 是事件入口和检查触发器；工作台后端、工具端权限及检查器共同执行边界。主 Agent 不能通过修改任务卡、shell 绕行或自填审批提高权限。
- 只读模板须由实际工具能力限制生产写；只有文本白名单而没有可验证限制时，不标为受控只读。初版 CLI 接力先在本地只读场景演练，接数仓前须验证能力边界。
- 生产授权记录对应用户、具体对象、动作、范围和产物版本；来源是实际用户授权，Agent 的 `approved=true` 或 gate 事件不构成用户批准。既有授权有效且覆盖当前动作时不重复请求。
- 输入、产物或检查器版本变化会使相关旧证据失效，暂停下游放行。静态通过、草稿回读、发布态、实例成功和数据正确分别保存证据，不能相互替代。
- 本地执行验收完成与 Teambition 业务任务完成分开显示。写评论、状态回写、生产提交或发布都使用适用的明确授权，并采用幂等记录避免重复动作。
- 输出限制在已存在的授权目录；检查真实路径与链接目标，禁止自动创建目录/worktree或扩大子 Agent 写权限。

### 轻量化与资源生命周期

- 首轮复用现有 Tauri/Rust、CLI、`data-mcp`、skills 和检查器；不增加云服务、内置浏览器或插件平台。
- 保留有界输出缓存、按任务的日志上限、失败退避与结束清理。输出截断须告知用户，关键失败证据不能静默丢失。
- 两个平台分别记录冷启动时间、空闲 RSS/CPU、执行中工作台与子进程开销、日志增长和退出残留。先取得基线并登记预算，再验收；未实测的性能目标不写成能力事实。
- 本地多入口共享账本不意味着多个 worktree 会自动共享记录；首版仅使用已有项目工作区和明确的单一账本位置。

### B1 第一切片：项目持久化与未派发恢复

项目存储使用既有 `local_data_dir()` 下固定 `agentterm-projects.json`，由后端启动时绑定；不能由renderer切换。每次读取/修改以伴随锁串行并重新读取磁盘，schema2/连续revision/摘要/1 MiB总日志/200项校验。修改在稳定锁内追加完整JSON快照并sync_all；Unix同步目录项。损坏或截断尾部失败关闭，不回退旧状态；旧候选pending也阻断并保留。读取不创建目录或数据文件。schema1单JSON可读取，下一次修改保留其字节并追加schema2快照，旧候选随后无法解析而失败关闭。移除仅改变项目记录，不删除项目目录；不保存敏感环境或原始日志。最后使用工具的记忆留待#6后续。

新命令 `recover_main_task_reservation` 只接收当前taskId/generation/revision与接管或释放选择，旧owner从账本读取。任务必须仍为reserved或recoveredReserved，文档不存在或其计划身份匹配且没有尝试事件；若接管还须核对已登记的真实项目。缺计划可在接管后用既有补全入口补齐，已有计划绝不覆盖。

OS确认旧PID不存在或句柄已结束后，在同一账本锁下CAS追加恢复结果。PID仍活着（即使其实已被复用）、无法查询、owner格式未知时继续保留占用；时间戳不作为PID复用后放行依据，保守拒绝可能需人工核实。Windows只请求SYNCHRONIZE并零等待查询，不读进程内存、不终止进程、不提权；Unix用signal0且仅ESRCH算退出。

接管保持taskId/generation和文档，变更owner、增加revision并写recoveredReserved；旧票据失效，旧程序不认识该阶段会失败关闭，不能继续读写整个账本。释放只允许上述未派发状态，保留所有任务文档。接管记录是兼容性边界，不能承诺旧程序直接回滚。所有派发必须先CAS离开预留状态再启动进程，因而不能在核实过程中绕过占用启动。

本切片不实现已派发尝试的停止证明或断点接续；这些能力进入#12。项目与任务存储分别提交，失败时显示错误并保持任务占用，不声称跨文件事务。

项目存储取舍（2026-11-20原生证据）：首候选同目录rename在本机返回错误17，原子替换无法落地；改用与任务记录一致的有界追加快照，锁内串行可见，截断尾部阻断后续写入。牺牲自动压缩与损坏时继续服务，换取无需移动/替换原文件及可审计历史；达到上限需显式归档方案，当前不自动删历史。

该切片已在应用6deebcf的Windows原生包验证，完整CI绑定e24ecfdd；两者差异仅为Windows测试兼容性修正。证据与仍未验证的范围见 [测试文档](testing.md)。#12 当前先保存启动意图与实际进程身份，再区分正常退出、停止不确定和结果待核实；不能把“父进程不存在”直接推广为已派发进程树或外部作业已停止。

### #12 当前切片：启动身份与停止证据（2026-11-21）

- `task_document` 的启动事件可在子进程实际创建并加入隔离范围后补写 `ProcessIdentity`，包含 PID、可执行文件和 Unix 可用的启动 token。写回只允许目标仍为 `Running` 的启动事件；相同身份重复写入幂等，不同身份拒绝覆盖。
- 追加日志的历史校验允许同一事件从“无身份”到“已记录身份”的单向补充，其他事件字段仍须保持不变；这保证身份回写不会破坏既有日志链，也不会把任意修改当成新历史。
- `run_recorded_with_control` 已接入幂等停止令牌：启动事件和进程身份落盘后，停止请求先写入仍处于 `Running` 的启动事件，再停止受管进程；相同请求不重复改写，不同原因拒绝覆盖。relay 随后写入 `Unknown` 终止事件和停止证据，确认失败仍保留主任务占用。
- `task_process::observe_process` 提供只读身份核实：无身份的启动事件标为 `LaunchUncertain`；身份匹配且仍存活为 `Alive`；PID 已消失为 `Exited`；启动 token 不匹配为 `Reused`；权限不足、旧记录无 token 或查询竞态为 `Unknown`。`task_relay::assess_recovery` 只生成这些评估，不修改文档和账本，也不据此自动重派或释放。
- `resume_recorded_after_recovery` 是显式人工确认后的后端接续入口：它重新读取账本和文档，只在所有未结束旧尝试都为 `Exited` 时，将账本从 `RecoveryRequired` CAS 迁移到新的 `RecoveredReserved` owner，再用新 revision 创建尝试。活跃、复用或未知状态阻断接续；旧 dispatch 回报无法通过新尝试的严格身份校验。
- 当前验证覆盖停止请求的确认与未确认分类、启动事件到终止事件的顺序、`RecoveryRequired` 占用保留、只读进程分类、显式接续迁移和迟到回报隔离；尚无前端停止/接续命令、真实 CLI 派发或外部作业撤销。接续失败继续保留占用，确认前不得切换任务或释放占用。

### 任务页交互与错误边界

未保存计划由应用根组件的内存状态持有，切换工作台/终端后恢复输入，关闭应用后不持久化；保存仍走原生计划命令。仅一个项目且没有历史选择时自动选中；已移除的选择要求重新选择，不自动换项目。原生添加项目从任务页直接调用既有选择器。

读取错误与操作错误分别展示：读失败暂停所有任务操作；命令失败后先回读，回读成功才允许纠正输入/再次操作。拒绝操作不再通过一个全局error永久禁用表单。仍保留请求序号、同步重复点击保护和后端任务/代次/版本检查。返回窗口触发一次核对，已有请求或变更期间不叠加；普通任务状态不做定时轮询，受控派发请求期间例外采用有界短轮询，以便展示后端已落盘阶段。

当前任务以目标、状态、工作范围、执行进度和交付文件组织；任务编号、绝对路径和摘要折叠展示。取消及核实释放需要二次确认，读状态变化使旧确认失效；只呈现现有后端能力，不增加真实派发或生产入口。

受控派发状态联动只读取既有 `workbench_snapshot`，不向当前手动终端注入输入，也不把终端输出解析成 Agent 语义。派发请求进行期间前端按 350ms 间隔读取快照，并通过账本 revision、generation 与任务文档 revision 丢弃旧快照；任务卡展示 `running`、`verifying`、`waitingInput`、`waitingApproval`、`pausing` 和 `recoveryRequired` 的人类可读说明。轮询结束后停止，短暂读取失败保留最近已知状态，不宣称完成。

受控派发在后台线程运行既有顺序 relay，避免同步 Tauri 命令阻塞停止入口。停止请求只允许当前任务 owner 在 `running/verifying/pausing` 阶段发起；后端先向当前运行事件追加停止原因，再请求共享 `ProcessControl`，然后以最新账本 revision 推进 `pausing`。relay 遇到该竞态时重新读取当前 revision；无法确认停止、进程残留或写入失败均保持占用并转待核实。停止确认、证据有效性和完成释放仍由后续切片提供。

### 手动 CLI 会话交互修复（2026-11-20）

任务页切换通过隐藏既有终端面板实现，会话、xterm屏幕与事件订阅保留；隐藏时不向PTY提交零尺寸，返回时按实际可用空间调整并恢复输入焦点。运行与结束状态在导航入口可见；关闭运行中CLI必须先确认，停止失败保留会话，停止与自然退出竞争时以原生快照核实。

终端通信集中在sessionTransport：先订阅退出/输出，再读取带字节偏移的快照，合并竞态输出；连接失败、超时或清理后的迟到响应不伪装成成功。输入最多一个在途请求、有界排队，失败立即阻断后续输入且不重发；输出等待缓存512 KiB、输入积压64 KiB、连接等待10秒，均为内存且不记录输入内容。显式重新连接只重建显示订阅，不调用start_session。

本轮仍保留原有手动终端的交互与可靠性边界；已接通受限的 `dispatch_controlled_task`，但没有接通任务队列或运行中恢复，也没有更改工具注册表、CLI参数或生产权限。真实工具账号兼容性及原生终端须分别验收。

### 双终端分屏与焦点（2026-11-20）

会话集合与布局分开：paneIds最多两个已有sessionId，activeId只标识当前输入面板；showLauncher暂时隐藏布局但保留paneIds。select已可见会话只切焦点，选择隐藏会话只替换当前格；从新建页启动时替换右侧。split优先同项目的另一会话，不发起CLI；single只隐藏另一侧；关闭后从当前布局移除该ID，其他会话和输出不变。

SessionWorkspace始终在同一父节点按sessionId挂载全部SessionPanel，分屏、单屏和新建页只改变grid位置与hidden，避免重建xterm。TerminalView的visible负责输入可用性和尺寸同步，focused/focusRequest只控制显式切换时的输入焦点；点击面板按钮更新当前面板但不把键盘焦点抢回终端。两个可见终端各自观察尺寸，隐藏终端不提交零尺寸，后台退出保持最后屏幕。

### 手动会话历史与再次打开（2026-11-21）

手动终端会话的启动与结束（自然退出、显式停止、应用退出清理）由 `session_history.rs` 写入 OS `local_data_dir()` 下的 `agentterm-session-history.json`，采用伴随 `.lock` 文件锁与 SHA-256 校验追加事件（schema=2、2 MiB 上限、最近 50 条读取窗口），损坏、缺锁或截断尾部均失败关闭且保留原文件。历史记录仅存会话 ID、工具 ID/名称、规范项目路径、起止时间戳、退出原因与可选输出字节数，不存屏幕内容、环境变量或凭据。

历史写入失败只打印标准错误而不中断或丢失正在运行的 CLI；前端 `useSessionHistory` 经 `session_history` 命令在新建页显示最近 5 条未存活会话，读取失败保持可见并提供重新读取入口，工具缺失或未安装时禁用“再次打开”并说明原因。点击“再次打开”会按原项目与原工具调用 `start_session` 启动全新终端进程；明确标注不恢复原进程内存、滚动缓存或 CLI 内部上下文。该机制独立于 `task_ledger` 与 `task_document`，不占用单主任务槽，也不表示已支持外部终端接管或 CLI 原生 `resume` 协议。

### Windows Codex 启动与终端乱码修复（2026-11-21）

- `tools.rs` 在 Windows 上跳过无扩展名 POSIX shell 包装（例如 npm `codex`）及 `.ps1`，优先解析 `.exe`/`.com`，其次 `.cmd`/`.bat`；对 `.cmd`/`.bat` 的版本检测通过 `cmd.exe /D /C` 并加 `CREATE_NO_WINDOW` 执行。
- `sessions.rs` 抽取 `build_pty_command` 与 `strip_windows_verbatim`：通过 PTY 启动 `.cmd`/`.bat` 包装时经 `cmd.exe /D /C` 调度；去除 `\\?\` 前缀并注入 `PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8` 及 `LANG`/`LC_ALL=C.UTF-8`；Windows 宿主控制台设为 UTF-8（CP 65001）并挂载 `WinJob` 清理派生子进程树；`trim_buffer_front` 回放裁剪时按行与 ANSI CSI/OSC 边界跳过残缺转义序列。
- `TerminalView.tsx` 补全 Windows CJK 等宽字体栈（`Cascadia Mono`/`Consolas`/`Microsoft YaHei`/`Noto Sans SC`）与 `windowsPty` ConPTY 属性；`offsetStitch.ts` 在 UTF-8 字节偏移拼接跨越中间字节时跳过残余 continuation bytes，防止出现 `\uFFFD`。真实桌面启动 Codex 与物理键盘交互待打新包后实测验证。
