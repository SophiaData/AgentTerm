## 硬约束（动架构、加依赖前逐条核对）

- 依赖白名单制：新依赖必须登记用途与理由；无理由不引入。
- 渲染进程禁止直接访问 Node.js、文件系统或任意进程；所有桌面能力通过受校验的 Tauri 命令暴露。
- AI 工具只能从已登记工具及其可执行文件路径启动；首版不接受前端传入任意 shell 命令。
- 项目路径必须是存在的目录；移除项目只改 AgentTerm 数据，不删除或修改项目文件。
- 一个会话只绑定一个 PTY；切换标签页不得重复启动进程，关闭运行中会话必须经确认。
- 终端输出通过事件发送；禁止无界缓存、无界循环和无界自动重试，退出后必须释放读取线程与句柄。
- 不在日志、事件、测试快照或提交中记录密钥、口令、令牌及完整敏感环境。
- 本地设置写入应用数据目录并采用原子替换；损坏时保留原文件并显示可理解的错误。
- 质量门必须包含格式、lint、类型检查、前端测试、Rust 测试和模板契约测试；不得以静态检查冒充运行测试。
- 发布保持手动；CI 可构建安装包，但不能因普通推送自动创建正式 Release。
- 首版只支持 macOS Apple Silicon（`aarch64-apple-darwin`）和 Windows x64；本地开发不要求完整 Xcode。

## 数据工作台运行契约（2026-11-19，首个后端切片）

本节约束工作台实现。现已实现的是 `task_ledger.rs` 的单任务预留账本和 `task_commands.rs` 的四个后端命令；完整编排、任务页面与 CLI 接力仍是后续工作。产品范围以 [PRD](PRD.md) 为准，开发接力纪律见 [workflow](workflow.md)，实施次序与测试清单见 [tasks](tasks.md)。

### 功能 9 当前实现与取舍

- 账本使用 Rust 标准库 OS 文件锁和带版本的追加记录，没有新增第三方依赖。初始化与所有读写先取得固定 `.lock` 伴随文件的锁，再创建或打开数据文件，避免首次建文件的空内容窗口被其他操作读取；单次读、校验与追加保持锁直到 `sync_all`。进程退出释放 OS 锁，但不释放持久任务占用。
- 首轮只记录当前占用、任务/项目/进程归属、代次、版本和阶段，无关系查询需求，因此暂不采用原规划首选的 SQLite。任务队列与完整事件索引增长到后续阶段时，再按迁移与并发测试评估事务数据库；不把当前文件实现称为通用数据库。
- 文件头版本、完整记录、校验和、连续版本及合法状态转换逐项验证；未知版本、截断尾部和损坏记录失败关闭，不截断或修复原件。文件上限 8 MiB，超限停止并提示归档，当前不提供自动归档。校验和仅检测意外损坏，不证明作者身份；同一 OS 用户恶意改写、删除或回滚整个文件不在该机制的保护范围内。
- 每个 OS 用户固定使用 Tauri `local_data_dir()` 下的 `agentterm-main-task-ledger.log` 与同名追加 `.lock` 的伴随文件；所有项目与窗口共用该位置。文件名不随 schema 版本变化，避免新旧程序通过另开账本绕过占用。目录必须已经存在，只在显式初始化命令中创建文件，不在启动或查询时建目录或文件。锁文件不移除或替换。
- 前端不能指定账本路径或进程归属；归属由后端生命周期生成，预留时核对已登记项目。重启后的旧归属显示 `recoveryRequired`，不允许自动取消或重领。
- 四个命令为 `task_ledger_initialize`、`task_ledger_snapshot`、`claim_main_task`、`cancel_main_task_reservation`。取消仅允许同一后端归属、相同代次与版本、尚未记录执行意图的 `reserved` 状态。
- `set_phase` 仅供后续可信原生调度器调用，不暴露给前端。进入运行、验收、等待、暂停或待核实后不能回到 `reserved`，也不能用取消预留释放。安全停止与完成释放属于后续恢复功能；本轮不提供自述“已停止”的通用释放接口。
- 当前没有调用 CLI 或线上系统，原有手动终端不经过账本。完整工作台约束只能在后续调度器接入后验收；当前证据证明受管账本操作的单占用，不证明所有终端已经单并发。

### 职责与持久状态

- 桌面沿用 Tauri/Rust，现有 TUI 保留启动入口；编排核心独立于界面，未来接入同一核心的入口共享同一个执行账本。
- 业务身份以 Teambition 的组织、项目和任务 ID 组合为准；本地 `task_id` 标识执行计划，`step_id` 标识步骤，`dispatch_id` 标识一次实际执行尝试。重试创建新尝试并引用旧尝试，不能覆盖旧证据。
- 现有项目与设置存储保持其职责。当前单任务占用使用上方受限追加账本；后续本地队列、步骤、尝试与证据索引按实际需求扩展，不复制第二份业务任务状态。
- 账本使用版本化 schema，未知版本或损坏记录失败关闭；迁移先备份并验证可恢复。数据文件使用已存在、经校验的目录，初始化不自动创建父目录。
- 产物引用至少包含路径、内容摘要、输入指纹、检查器版本和产生时间。原始日志按需引用并有容量上限；认证信息和敏感环境不进入账本、日志、测试快照或同步内容。

### 单主任务与执行顺序

- `max_active_main_tasks = 1` 是同一本地应用实例体系跨项目、跨窗口、跨受管入口的硬约束，不是每个项目各有一个名额。多进程打开同一账本时也须原子竞争唯一占用。
- 首版 `max_active_dispatches = 1`，执行与验收顺序接力。主任务等待执行者时，主 Agent 只协调该任务；派发子任务不能成为另开主任务的理由。
- 运行、验收、等待输入、等待授权、正在暂停、故障待核实均保留主任务占用。完成或取消前核实执行者及关联外部作业已结束；安全暂停须保存断点且确认已停止或可安全接续后才能释放占用。
- 占用、代次、步骤转换和事件写入必须原子化；同时启动只允许一个成功。前端禁用按钮只作体验提示，Rust 入口和账本仍必须检查。
- 手动终端能力维持历史用途；它不自动受账本控制。接入受管任务必须登记归属并经过同一检查，不能用手动入口绕过受管派发。工作台不宣称控制用户在应用外另起的 CLI。

### 执行适配与结果回报

- 已登记适配器提供能力发现、启动、输入、状态、结果回报、停止与恢复核实。差异由适配器显式声明，不假定所有 CLI 都能恢复原会话或都提供同样的 hooks。
- 每次派发包含任务/步骤/尝试 ID、目标、已确认事实、输入版本、读写范围、允许工具、验收标准和产物位置。默认验收模板标为候选，不冒充业务方确认。
- Agent 报告「完成」、CLI 退出0或收到 Stop 仅触发结果收集；必须检查结构化结果、产物和证据。CLI 缺少结构化能力时，使用经验证的包装协议；无法验证则返回待核实。
- 执行者交回确定版本并停止修改后，才启动独立审查上下文。业务与规范审查分别保存结果；作者不得充当自己的独立审查者。
- 同一事件按尝试 ID 与事件 ID 去重；只允许当前代次推进当前步骤。旧尝试的迟到结果可保留审计，但不能将新尝试或新任务标记完成。

### 中断、停止与恢复

- 启动前先记录派发意图；进程创建前后崩溃必须能区分待启动、已启动和未知。不能为了恢复方便直接重复创建进程。
- 重启后先核实执行者、工具调用及外部实例状态，之后才决定重新连接、接续或创建新尝试。PID 可能复用，需结合实际启动身份，不能单靠 PID 或心跳超时判断进程已结束。
- Stop 请求、超时、窗口关闭和失联都不等于执行者或外部作业已停止。未知状态保持占用并提示人工核实；取消主任务不冒充撤销已提交的外部作业。
- 结果未知的外部操作先按实例或请求引用查明；只有能够证明未执行且允许安全重试，才提交新的尝试。自动重试须有有限预算和明确类别，禁止无限重试。
- 新旧实现同时运行、重复派发、迟到回报、退出残留与跨窗口竞争都是必测失败场景，不能只测试顺利完成。

### 权限、hooks 与业务验收

- hooks 是事件入口和检查触发器；工作台后端、工具端权限及检查器共同执行边界。主 Agent 不能通过修改任务卡、shell 绕行或自填审批提高权限。
- 只读模板须由实际工具能力限制生产写；只有文本白名单而没有可验证限制时，不标为受控只读。初版 CLI 接力先在本地只读场景演练，接数仓前须验证能力边界。
- 生产授权记录对应用户、具体对象、动作、范围和产物版本；来源是实际用户授权，Agent 的 `approved=true` 或 gate 事件不构成用户批准。既有授权有效且覆盖当前动作时不重复请求。
- 输入、产物或检查器版本变化会使相关旧证据失效，暂停下游放行。静态通过、草稿回读、发布态、实例成功和数据正确分别保存证据，不能相互替代。
- 本地执行验收完成与 Teambition 业务任务完成分开显示。写评论、状态回写、生产提交或发布都使用适用的明确授权，并采用幂等记录避免重复动作。
- 输出限制在已存在的授权目录；检查真实路径与链接目标，禁止自动创建目录/worktree或扩大子 Agent 写权限。

### 轻量化与资源生命周期

- 首轮复用现有 Tauri/Rust、CLI、`data-mcp`、skills 和检查器；不增加云服务、内置浏览器或插件平台。
- 保留有界输出缓存、按任务的日志上限、失败退避与结束清理。输出截断须告知用户，关键失败证据不能静默丢失。
- 两个平台分别记录冷启动时间、空闲 RSS/CPU、执行中工作台与子进程开销、日志增长和退出残留。先取得基线并登记预算，再验收；未实测的性能目标不写成能力事实。
- 本地多入口共享账本不意味着多个 worktree 会自动共享记录；首版仅使用已有项目工作区和明确的单一账本位置。
