# 架构与技术约束

> 维护人：技术合伙人。老板不需要读本文件。版本以 `pnpm-lock.yaml` 与 `src-tauri/Cargo.lock` 为准，本表记录 2026-11-17 核对的选型与理由。

## 技术栈

| 层       | 选型                                                       | 一句话理由                                                     |
| -------- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| 桌面外壳 | Tauri 2（CLI 2.12.5）                                      | 使用系统 WebView，安装包较轻，支持 macOS 菜单栏与 Windows 托盘 |
| 终端后端 | Rust + portable-pty 0.9.0                                  | 跨平台管理真实 PTY，支持交互输入、输出、缩放和退出             |
| 前端     | React 19.3.1 + TypeScript 6.0.3 + Vite 8.3.8               | 类型明确、生态成熟，适合项目列表与多标签界面                   |
| 终端显示 | @xterm/xterm 6.0.0 + @xterm/addon-fit 0.11.0               | 成熟呈现 ANSI 输出并适配窗口尺寸                               |
| 数据     | 应用数据目录中的 JSON 文件                                 | 只保存项目与设置，无需数据库或云服务                           |
| 测试     | Vitest 5.1.0 + Rust `cargo test` + Python `unittest`       | 分别覆盖前端、终端后端和模板治理契约                           |
| 质量     | ESLint 10 + Prettier 3.10.1 + `cargo fmt` + `cargo clippy` | 统一静态检查，减少跨语言回归                                   |
| 构建发布 | GitHub Actions + `tauri-apps/tauri-action@v1`              | 手动触发/打标签后构建 macOS arm64 与 Windows x64 安装包        |

## 硬约束（动架构、加依赖前逐条核对）

- 依赖白名单制：新依赖必须登记用途与理由；无理由不引入。
- 渲染进程禁止直接访问 Node.js、文件系统或任意进程；所有桌面能力通过受校验的 Tauri 命令暴露。
- AI 工具只能从已登记工具及其可执行文件路径启动；首版不接受前端传入任意 shell 命令。
- 项目路径必须是存在的目录；移除项目只改 AgentTerm 数据，不删除或修改项目文件。
- 一个会话只绑定一个 PTY；切换标签页不得重复启动进程，关闭运行中会话必须经确认。
- 终端输出通过事件发送；禁止无界缓存、无界循环和无界自动重试，退出后必须释放读取线程与句柄。
- 不在日志、事件、测试快照或提交中记录密钥、口令、令牌及完整敏感环境。
- 本地设置写入应用数据目录并采用原子替换；损坏时保留原文件并显示可理解的错误。
- 质量门必须包含格式、lint、类型检查、前端测试、Rust 测试和模板契约测试；不得以静态检查冒充运行测试。
- 发布保持手动；CI 可构建安装包，但不能因普通推送自动创建正式 Release。
- 首版只支持 macOS Apple Silicon（`aarch64-apple-darwin`）和 Windows x64；本地开发不要求完整 Xcode。

## 决策记录（ADR-lite：只记「为什么」，防止日后翻案无据）

| #   | 日期       | 决策                                           | 理由                                   | 被否的替代方案及原因                                                     |
| --- | ---------- | ---------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------ |
| 1   | 2026-11-17 | 用 Tauri 2 + Rust，不要求本地 Xcode            | 双端、轻量、GitHub Runner 可完成构建   | 原生 Swift：无法覆盖 Windows；Electron：体积较大且原生终端模块打包更复杂 |
| 2   | 2026-11-17 | 界面用 React/TypeScript                        | 项目与标签页界面需要可维护的组件和类型 | 纯 Rust 界面：终端呈现与双端界面成本偏高                                 |
| 3   | 2026-11-17 | 用 xterm.js + portable-pty                     | 分别解决终端显示与真实交互进程管理     | 普通子进程管道：不能可靠支持交互式 CLI；自研终端：风险高                 |
| 4   | 2026-11-17 | 首版数据用 JSON                                | 数据量小、可备份、无额外服务           | SQLite：当前无查询与关系需求，首版不必要                                 |
| 5   | 2026-11-17 | GitHub Actions 构建 macOS arm64 与 Windows x64 | 无本地 Xcode，公开仓库可复现构建       | 本机手工打包：双端环境难维护；自动正式发布：未经验收不应发布             |
