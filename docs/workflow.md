# 协作手册（迭代协议全文）

> 本手册是项目的法律，CLAUDE.md 是它的速记。修订本手册须向老板给一句白话理由并记入 CHANGELOG。
> 本文件自含，日常无需回读立项 skill。

## 1. 角色

- **老板 = 产品经理**：定需求、定优先级、验收成品；不做技术决策，不需要看代码。
- **技术合伙人 = 主会话**：全部工程职责——规划、实现、质检、文档、汇报；口号是「老板掌舵，我执行」。

### 主 Agent 单任务推进

- 本手册约束开发 AgentTerm 的工作方式；产品运行时的单并发约束另见 [架构文档](architecture.md)，两者都不能靠提示词代替运行机制。
- 主 Agent 同时只推进一个主任务。接单、派发、实施、审查、整合按顺序进行；委派后只处理该任务的状态、提问与结果，不开展另一任务。
- 初版采用顺序接力：执行者交回产物并停止修改后，独立审查者读取确定版本；审查结束后主 Agent 才继续修改。审查者与实施者使用独立上下文，业务与规范审查分别保存结论。
- 待处理任务统一排队。插队须先保存断点并确认当前执行者和外部作业已结束或安全暂停；状态未知时保留当前任务占用，先恢复或核实。
- 本次产品规划不会把旧功能的「待验收」改成「完成」。进入新功能实现前，先按台账处理基础功能验收与既有质量门。

## 2. 功能循环（每个功能走一遍，顺序不可跳）

1. **取活**：docs/tasks.md 里最靠前且前置已完成的「待办」→ 状态改「进行中」（全表同时只许一个）。
2. **对齐**：产品行为若有多种合理理解 → 用选择题问老板（一次最多 3 问，只问产品问题）；L 规模功能必须先写清验收结果再动工。
3. **实现**：小步走，每到可运行状态就 commit（`feat(#编号): 白话描述`）；技术共识写入对应文档。
4. **自检**：
   - a. 质量门单命令全绿。
   - b. 新逻辑有对应测试；关键行为做一次变异自检——故意改坏实现、确认测试变红、再安全还原。
   - c. 对照台账验收标准逐条核对。
   - d. diff 复查：无密钥、无越界改动；范围外问题记入 tech-debt.md。
5. **QA 评审**（M/L 必做，S 可免）：实施结束并冻结待审版本后，派一次性 qa-reviewer 子代理独立出具 PASS / FAIL+编号理由；主 Agent 在此期间只等待或回答当前审查问题。FAIL 返工后重新自检。同一功能第 3 次 FAIL 必须停下请老板拍板。
6. **收尾**：tasks.md 状态改「待验收」；CHANGELOG.md 加白话记录；同步行为文档。
7. **汇报**：按第 5 节汇报；老板亲手验证点头后，状态改「完成」并归档。

**计划外来件**

- 新想法先翻译成功能台账，确认插队还是排队；默认不打断进行中功能。
- 缺陷优先排队；插队仍须按上方单任务规则完成暂停与交接。修复必须附防复发测试并记入 CHANGELOG。
- 一切来件先落台账再动手。

## 3. 质量门

- 单命令：`pnpm check`，依次执行格式检查、ESLint、TypeScript 类型检查、Vitest、Rust 格式/Clippy/测试及模板契约验证。
- 全绿才许 commit；禁止删除、跳过或改弱既有测试使其变绿。确需改变测试语义，汇报时必须单独说明。
- 冒烟标准：`pnpm dev:app` 一条命令把产品跑起来，随时可向老板演示。
- 双端安装包由 GitHub Actions 构建；普通质量检查不自动创建正式 Release。

## 4. QA 子代理评审要点

- 不听主会话自评，自己检查实际 diff 与测试证据。
- 验收标准逐条核对，复跑质量门，并对 1–2 个关键行为做变异测试抽查。
- 按 architecture.md 硬约束扫描 diff，检查密钥泄漏和越界改动。
- 只报影响正确性、验收或硬约束的问题，不做风格挑刺。
- 结论只有 PASS / FAIL+编号理由，末尾附 2–3 句白话摘要。

## 5. 向老板汇报模板

```text
【汇报】功能 #N：名称
- 做成了什么：一句白话，说用户能干什么了
- 你怎么验证：一步操作 + 预期看到什么
- 要注意的：风险 / 限制 / 花销；没有写「无」
- 下一步建议：下个功能 + 一句为什么
- 需要你拍板：产品选择题；没有写「无」
```

## 6. 会话与成本纪律

- 事件驱动，不设定时轮询；老板说「继续」即接力。
- 新会话按 CLAUDE.md 启动协议恢复，不通读全部文档。
- 长任务可在后台执行，但主 Agent 保持当前任务归属；子代理用于有边界的执行或独立 QA，按顺序交接。
- 每个功能收尾后是安全断点，状态必须落在文件里而非只在对话中。
- 老板说「连着做完 M1」时逐功能走完整循环，全部到「待验收」后一次汇报。

## 7. 承重审计（每个里程碑收口时做）

1. 检查每条流程仍在防什么失败，不再需要的规则经说明后精简。
2. 盘点 tech-debt.md：清账、降级或立项。
3. 修正过期文档与交叉引用。
4. 收口时产品必须处于可试用状态；正式发布单独立项，不临时突击。
5. 问老板：「流程哪里让你觉得烦？」
