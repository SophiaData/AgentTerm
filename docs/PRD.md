# AgentTerm · 产品需求（PRD）

> 2026-11-19 产品方向更新。本页描述待开发的工作台；当前代码仍是 CLI 管理底座。功能状态以 [台账](tasks.md) 为准，本次不改变历史功能验收结论。

## 一句话

本地优先的轻量数据开发 Agent 工作台：用户交给它一项任务，工作台组织专业 Agent 顺序接力，展示进度、产物、证据和需要用户决定的事项。

## 用户与使用方式

首版服务使用 Mac Apple 芯片或 Windows x64 的数据开发者。用户从一个入口接需求、看进度、做决定；任务涉及查数、异常排查、建模、存量改造、迁移与节点交付。

当前迭代只推进一项主任务，其他任务排队。主 Agent 负责拆步骤和汇总；执行者负责当前步骤；独立验收者核对确定版本的产物。角色按任务选择，不绑定特定模型。

## 单并发是产品约束

- 同一个本地工作台中，跨项目、跨窗口同时最多一个正在推进的主任务。第一版执行者与验收者也依次工作。
- 等待执行者、审查、输入、授权或故障核实时，当前主任务仍占用执行位置。
- 用户切换任务前，工作台保存断点，并确认原执行者与外部作业已结束或安全暂停；无法确认时显示待核实，不开始另一项。
- Agent 结束发言或退出进程后，任务进入结果核对。只有验收要求满足、产物与证据对应，才标记本地执行完成。
- 现有手动终端会话不自动成为受控任务，也不代表该约束已经实现。接管会话时必须先登记归属并通过同一派发检查。

## 工作台首页

一张任务页分三部分：

- 左侧：项目与任务队列，区分排队、当前任务、待决定、待验收和已交付。
- 中间：目标、步骤、当前 Agent、最近进展和阻塞原因。
- 右侧：SQL、设计文档、差异、检查报告、证据引用和需要授权的动作；终端按需展开。

用户能直接看出「谁在做什么、为什么停下、下一步需要我做什么」，无需逐个翻终端寻找结果。

## 首个完整场景：只读异常排查

1. 用户从 Teambition 选择一项任务，查看项目归属、原始描述和待核实问题。
2. 主 Agent 提出步骤和验收条件，缺少业务决定时先列出缺口。
3. 调度与数据执行者按顺序取得实例、分区或对账证据，记录查询时间与范围。
4. 独立验收者核对证据是否支持结论；不足则退回补充，限制单独列出。
5. 主 Agent 交付统一报告，任务页保留产物和证据引用。业务任务状态的回写单独列为可授权动作。

该场景只使用读取能力。后续建模阶段交付本地设计与 SQL 草稿；迁移、节点和生产动作在后续里程碑中按具体对象授权。

## 首版必须具备

| 能力       | 用户可观察的结果                                                     |
| ---------- | -------------------------------------------------------------------- |
| 任务接入   | 选中任务后看到正确项目和原文；重复导入不会重复排队                   |
| 单任务派发 | 连续点击、多个窗口或两个项目同时启动时，只有一个主任务获得执行位置   |
| Agent 接力 | 每一步有负责人、范围、完成条件；执行者交回产物后才启动验收           |
| 证据与产物 | 同一任务下查看 SQL、Markdown、差异和检查结果；过期证据会标记失效     |
| 阻塞与恢复 | 明确显示等待原因；重启后核实旧执行状态，不自动重复提交未知状态的操作 |
| 工具异常   | 工具缺失、鉴权失败、断线和启动失败都有可操作的原因说明               |
| 成本可见   | 分别查看工作台与 Agent 子进程的资源消耗，日志和缓存有上限            |

支持的 CLI 通过已登记适配器接入；初版先完成两种 CLI 的同一协议验证，再按验证结果增加工具。复用其现有账号与会话机制，不把凭据复制进任务记录。

## 记录与授权

- Teambition 保存业务任务、优先级与最终业务状态。工作台只保存执行步骤、尝试、阻塞和证据引用，并关联来源任务。
- 项目仓库保存 SQL 与设计交付物。知识通过现有审核入口提交候选，不复制出另一套规范库。
- 本地验收通过与外部系统任务完成分别显示；写评论、改业务状态需要适用的用户授权。
- 生产授权须覆盖具体表或节点、动作和范围，并对应当前产物版本。已覆盖的步骤不重复询问；范围或产物变化后重新判断授权是否仍有效。
- 数据工具沿用本地 `data-mcp`；本项目不新建数据库客户端，也不保存 Cookie、令牌或认证头。
- 所有输出先核对已存在的父目录；不自动创建目录、worktree 或 DataWorks 文件夹。

## 轻量化边界

保留任务派发、交接、证据、验收与恢复的完整流程。第一版不包含远程执行、手机端、云同步、插件市场、内置浏览器、完整编辑器、自动安装升级 CLI 或无人授权的生产发布。

以现有 Tauri 桌面任务页作为工作台入口；TUI 保留现有工具启动用途，首轮不重复建设两套工作台界面。桌面与后续 TUI 接入同一编排核心时，须共享任务归属和并发检查。

资源验收记录冷启动、空闲内存与 CPU、执行中总开销、日志增长、退出残留；工作台与子进程分别计量。第一轮先测基线并确定预算，再据此验收，当前没有已测的性能承诺。

## 迭代顺序与成功标准

1. **任务能接力**：先实现任务身份、单任务占用、执行记录与恢复，再接 CLI。离线替身验证异常分支，真实 CLI 完成只读任务接力，重启后可恢复。
2. **需求能交付**：接入 Teambition 和已有只读数仓能力，以真实授权的只读排障完成「接单到报告」。历史案例回放与当前线上验证分别标记。
3. **草稿能验收**：模型设计、字段清单、调度计划、DDL/DML 草稿及门禁结果一致，独立审查能发现遗漏。
4. **生产动作受控**：迁移、节点和补数据按具体对象授权，执行后通过权威通道回读；本阶段另行细化。

拆分与可复跑验收见 [功能台账](tasks.md)；任务身份、状态、权限和恢复的技术契约见 [架构文档](architecture.md)。
